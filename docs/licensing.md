# Licensing and reuse

A repository's own LICENSE file defines its license. These guidance files do not grant a license to other repositories, generated applications, Oracle branding, or third-party dependencies. GitHub's default community files do not supply an inherited repository license.

The three repositories in this workspace currently have no root LICENSE file. Before publishing or inviting external reuse, the repository owner must confirm an approved license with the appropriate rights holder and add its exact text to each repository. Do not infer an open-source license from public visibility or copy a license into every repository without that decision.

For each new project or transfer:

- Record the rights holder and approved license in the repository; link it from the README.
- Check the licenses and required notices for dependencies, copied examples, images, fonts, and other assets.
- Preserve applicable notices and document any restrictions on distributing an application or installer.
- Confirm permission to use Oracle names, logos, and other branding; a source-code license does not establish trademark permission.

Contributors should submit only work they have the right to contribute and identify third-party sources. These steps provide a decision checklist, not a legal approval or a new contribution agreement.
